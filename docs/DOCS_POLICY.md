# Политика документации

Репозиторий разделяет долговечные объяснения и факты, которые генерируются
текущей реализацией.

Для утверждений, предназначенных для оценки, приоритет такой: код и fixtures →
сгенерированные примеры → этот слой текущей документации (`README.md`, `docs/`)
→ исследовательские материалы. Исторические планы и snapshots в `research/` не
переопределяют поведение текущего checkout и должны иметь явную пометку
`ИСТОРИЧЕСКАЯ ИДЕЯ` или `historical`.

| Артефакт | Назначение | Source of truth | Способ обновления |
|---|---|---|---|
| `README.md` | точка входа для пользователя и оценки | стабильное описание, артефакты репозитория и benchmark JSON | текст редактируется вручную; updater владеет отмеченными блоками возможностей и статуса |
| `docs/ARCHITECTURE.md` | текущая архитектура и инварианты | `lib/`, profiles и проверенные design rules | вручную, с review |
| `docs/BENCHMARK.md` | методика и текущие метрики | benchmark JSON и RSpec JSON от runners | методика вручную; updater владеет отмеченным metrics block |
| `docs/DEMO.md` | воспроизводимый сценарий Web UI/CLI | реальные команды, UI labels и результат генератора | вручную; без выдуманного результата |
| `docs/DEVELOPMENT.md` | workflow для разработчика | scripts и tests репозитория | вручную, с review |
| `docs/GLOSSARY.md` | единый словарь терминов | согласованная терминология проекта | вручную, при появлении новых терминов |
| `examples/novapay/` | каноническая сгенерированная проекция | NovaPay fixture, profile, defaults и generator | `ruby bin/update_examples`; вручную не редактировать |
| `THIRD_PARTY.md` | зависимости и manifest лицензий | `Gemfile`, `Gemfile.lock`, gemspec и gem metadata | обновлять при изменении dependencies |
| `research/` | дополнительные доказательства и историческое исследование | benchmark corpus и research decisions | snapshots могут быть историческими; актуальные результаты — в `docs/` |

## Updater-ы

`bin/update_examples` пересоздаёт только `examples/novapay/`, копирует
committed fixture как `provider_api.yaml`, запускает настоящий generator и
завершается ошибкой, если verification не прошла.

`bin/update_docs` запускает настоящий mutation benchmark, Aurora benchmark и
RSpec suite, затем заменяет только отмеченные сгенерированные блоки в README и
`docs/BENCHMARK.md`. Для одинаковых входов он детерминирован и не добавляет
timestamps в документацию репозитория.

Числа benchmark не дублируются вручную в исследовательских заметках. Канонический
актуальный aggregate находится в сгенерированных блоках README и
`docs/BENCHMARK.md`; подробные research reports могут сохранять исторические
снимки с датой и статусом.

Если исходный результат отсутствует или marker повреждён, updater обязан
завершиться ошибкой, а не сохранять устаревшие числа и не придумывать замену.
